# Rules

Generated by `skill_verdict_score.py --list-rules --format markdown`. Severity is the default; some rules lower it when the text is clearly a warning.

## Validity (25 points)

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| V001 | error | File is not named SKILL.md exactly | Agents look for the exact file name SKILL.md. A different case is skipped on case-sensitive systems. | Rename the file to SKILL.md. |
| V002 | error | Frontmatter is missing or never closed | Every skill starts with a YAML block between two lines of three dashes. Without it the skill cannot load. | Add the block at the very top of the file and close it with a second line of three dashes. |
| V003 | error | The name field is missing | The name identifies the skill and is required by the spec. | Add name: with a lowercase, hyphenated identifier. |
| V004 | error | The description field is missing or empty | The description is the only text the agent sees before deciding to use the skill. | Add description: saying what the skill does and when to use it. |
| V005 | error | Name uses characters the spec does not allow | The spec allows lowercase letters, numbers and hyphens, with no leading, trailing or doubled hyphens. | Rename to something like pdf-form-filler. |
| V006 | error | Name is longer than 64 characters | The spec caps the name at 64 characters. | Shorten the name. |
| V007 | warn | Name does not match the folder name | The spec says the name must match the parent directory name. Mismatches break some installers. | Rename the folder or the name field so both are identical. |
| V008 | error | Description is longer than 1024 characters | The spec caps the description at 1024 characters; uploads and validators reject longer ones. | Cut it down and move detail into the body of SKILL.md. |
| V009 | warn | Name starts with a reserved prefix | Anthropic's authoring guidance says to avoid names that start with claude- or anthropic-. | Pick a name that does not start with those prefixes. |
| V010 | error | Frontmatter is not valid YAML | An unquoted colon followed by a space, an unterminated quote or a line that is not key: value breaks strict YAML parsers. | Wrap the value in double quotes, or use a block scalar with a greater-than sign. |
| V011 | warn | A hash sign silently cuts the value short | In an unquoted YAML value, a space followed by a hash sign starts a comment, so the rest is dropped. | Wrap the value in double quotes. |
| V012 | warn | Value starts with a character YAML treats as syntax | A leading bracket, brace, asterisk, ampersand, exclamation mark, percent sign, at sign or backtick changes how YAML reads the value. | Wrap the value in double quotes. |
| V013 | info | Frontmatter key is not part of the open spec | Keys outside name, description, license, compatibility, metadata and allowed-tools are ignored by strict validators. | Keep it only if your agent supports it; otherwise move it under metadata. |
| V014 | error | Compatibility is longer than 500 characters | The spec caps compatibility at 500 characters. | Shorten it to the real requirements. |
| V015 | error | Frontmatter is indented with tabs | YAML forbids tabs for indentation. | Use spaces. |
| V016 | error | The body is empty | A skill with frontmatter but no instructions gives the agent nothing to follow. | Write the instructions below the frontmatter. |
| V017 | error | SKILL.md points to a file that does not exist | The agent will try to open it and fail, or invent its contents. | Create the file or fix the path. |
| V018 | warn | Windows-style backslash path | Backslash paths break on macOS and Linux. Anthropic's guidance says to use forward slashes. | Use forward slashes in every path. |
| V019 | warn | Reference files link to other reference files | Anthropic's guidance warns that agents may read only part of a file that is reached through another reference. | Link every reference directly from SKILL.md, one level deep. |
| V020 | error | SKILL.md is not valid UTF-8 | Agents expect UTF-8 text; other encodings produce garbled instructions. | Re-save the file as UTF-8. |
| V021 | error | A Python script has a syntax error | The script will crash the first time the agent runs it. | Fix the syntax error. |
| V022 | error | A JSON file is not valid JSON | Tools that read the file will fail. | Fix the JSON syntax. |
| V023 | error | The description is not a plain string | A list or mapping where a text description belongs is read as a different type by agents. | Write the description as a single text value. |

## Triggering (25 points)

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| T001 | warn | Description is too short to trigger reliably | With a handful of words the agent has little to match against a request. | Say what the skill does, then add a Use when clause with real trigger phrases. |
| T002 | warn | Description never says when to use the skill | Anthropic's guidance asks for both what the skill does and when to use it. The when part drives triggering. | Add a clause that starts with Use when, followed by the situations and phrases that should activate it. |
| T003 | info | The when-to-use cue appears late in the description | Some Claude Code versions cut the menu text at 250 characters, so a cue placed after that can be lost. | Put the trigger clause in the first 250 characters. |
| T004 | warn | Description is written in first or second person | Anthropic's guidance says to write descriptions in third person because they are injected into the system prompt. | Rewrite as Processes X. Use when the user asks for Y. |
| T005 | warn | Description is vague | Phrases like helps with or a tool for match everything and nothing, so the skill fires wrongly or never. | Name the concrete task, file types or outputs. |
| T006 | warn | Name is generic | Names like helper, utils or documents say nothing about the skill and collide with other skills. | Use a specific name such as pdf-form-filler. |
| T007 | info | Description is longer than 250 characters | Some Claude Code versions truncate the menu text at 250 characters. Longer text still works but its tail may not be seen. | Front-load the most important triggers or shorten. |
| T008 | warn | Description is almost the same as the name | A description that only repeats the name adds no matching signal. | Describe the task and the trigger situations. |
| T009 | info | No literal trigger phrases, quotes or file types in the description | Concrete phrases the user might actually type make activation more reliable. | Add a few quoted phrases, file extensions or slash commands. |
| T010 | warn | Description is close to the 1024 character limit | Long descriptions eat the shared listing budget that all skills draw from. | Trim it to the essentials. |
| T011 | warn | Two skills have very similar descriptions | When descriptions overlap the agent cannot tell which skill to use, so either may fire or neither. | Make each description name a different task, and add a Do not use for clause. |
| T012 | warn | Description contains XML or HTML tags | Tags inside the description can be misread as structure by the agent or rejected by validators. | Remove the tags and describe in plain sentences. |
| T014 | info | Description contains headings or bullet lists | Descriptions work best as one short paragraph. | Rewrite as one paragraph. |

## Weight (20 points)

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| W001 | warn | SKILL.md is longer than 500 lines | The spec recommends keeping the main file under 500 lines and moving detail to reference files. | Move detail into references/ and link to it from SKILL.md. |
| W002 | warn | SKILL.md body is heavy in tokens | The spec recommends under 5000 tokens. The whole body loads into context each time the skill triggers. | Split rarely needed material into reference files that load on demand. |
| W004 | warn | Long reference file has no headings | Without headings an agent cannot jump to the right section, so it reads or skims the whole file. | Add headings, and a contents list for very long files. |
| W005 | warn | Large file in the skill folder | Big files slow installs and can flood the context if the agent reads them. | Remove it, shrink it, or fetch it at run time. |
| W006 | info | The skill folder holds a very large number of files | Hundreds of files make a skill hard to review and slow to install. | Trim the folder. |
| W007 | warn | SKILL.md contains a very large amount of inline code | Long code blocks in the body cost tokens every time the skill triggers. | Move the code to scripts/ so the agent can run it without reading it. |
| W008 | warn | SKILL.md contains an extremely long line | Very long lines are usually pasted data or minified content that waste context. | Move the data to a file. |
| W009 | info | Repeated lines in SKILL.md | Repetition costs tokens and can dilute emphasis. | State each instruction once. |

## Security (20 points)

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| S001 | critical | Hardcoded secret or private key | A key committed in a skill is leaked to everyone who installs it. | Remove it, rotate the credential, and read secrets from the environment. |
| S002 | critical | Hidden Unicode control characters | Invisible tag or bidirectional characters can smuggle instructions the human reviewer cannot see. | Delete the characters and retype the text. |
| S003 | error | Downloads remote code and runs it | Running whatever a URL serves hands control to that server, and it can change after you review it. | Download to a file, check a pinned checksum, then run it. |
| S004 | error | Hidden or encoded payload | Decoding data and running it, or hiding a command behind escapes and character codes, is the standard way to hide what a script really does. | Ship the plain script instead. |
| S005 | warn | Dynamic code execution or shell invocation | Evaluating strings as code or going through a shell opens the door to injection. | Call the function or program directly with an argument list. |
| S006 | warn | Touches credential or sensitive paths | SSH keys, cloud credentials, browser stores and password files are what a malicious skill goes after. | A skill almost never needs these; remove the access or justify it clearly in SKILL.md. |
| S007 | warn | Contacts a paste, tunnel, webhook or raw-IP endpoint | These hosts are common drop points for exfiltrated data and for staged payloads. | Use a named, documented API host, or remove the call. |
| S008 | warn | Reads or dumps the whole environment | Environment variables often hold tokens. Dumping them all is a classic way to steal secrets. | Read only the specific variable you need. |
| S009 | warn | Destructive command | Commands that wipe a home folder, a disk or permissions can destroy data if the agent runs them. | Delete only a specific, validated path, and ask for confirmation first. |
| S010 | warn | Privilege escalation | Skills should not need administrator rights. | Remove it, or explain why it is needed. |
| S011 | error | Instruction-override, impersonation or concealment language | Text that tells the agent to drop its rules, pretends to come from the system or from Anthropic, or hides actions from the user is a prompt-injection signature. In the description it reaches every conversation, so it is critical there. | Remove it. A skill should add guidance, never remove safeguards. |
| S012 | warn | HTML comment that hides instructions | Comments are invisible when the file is rendered but still read by the model. | Delete the comment or move it into visible text. |
| S013 | warn | allowed-tools grants unrestricted shell access | A bare shell permission lets the skill run any command without asking. | Restrict it to the specific commands the skill needs. |
| S014 | info | Installs packages or downloads and runs files at run time | Runtime installs pull unreviewed code into the environment. | Pin versions and document what is installed. |
| S015 | warn | Obfuscated or encoded blob | Long encoded strings and escape chains hide what the file really contains. | Replace with readable source or a plain data file. |
| S017 | error | Modifies startup files, scheduled jobs, git hooks or authorised keys | Persistence mechanisms keep running after the skill is gone. | Remove it, or make it explicit and opt-in. |
| S018 | warn | Symlink points outside the skill folder | A link can expose any file on the machine through the skill. | Replace it with a real file. |
| S019 | info | Script capability | Shows what a script can do (network, subprocess, delete) so a reviewer knows where to look. | Informational: review the script for these actions. |
| S021 | warn | Asks to bypass permission or sandbox safeguards | Skills that tell the agent to skip approvals or leave the sandbox remove the user's last line of defence. | Remove the instruction. |
| S022 | critical | Sends secrets or private data out | Reading keys, tokens or the whole environment and sending them over the network (or telling the agent to share them) is data theft. | Remove it. A skill must never move credentials or private files anywhere. |
| S023 | critical | Reverse shell or remote control | Wiring a shell to a network socket gives a stranger control of the machine. | Remove it. No skill needs a reverse shell. |
| S024 | warn | Loads instructions from the internet at run time | Instructions fetched when the skill runs can change after you review it, so the reviewed skill is not the one that runs. | Ship the instructions inside the skill, or pin the exact content with a checksum. |
| S025 | error | Leaks chat data through an image or link URL | An image whose URL carries conversation data sends that data to the host the moment it is rendered. | Remove the template from the URL. Never build image URLs from chat content. |
| S026 | warn | Changes the agent's own settings, memory, skills or permissions | A skill that edits the agent's settings, CLAUDE.md, skills or allowed tools can quietly grant itself more power or plant instructions for later sessions. | Remove it, or ask the user to make the change themselves and show the exact edit. |
| S027 | warn | Turns off TLS certificate checks | Without certificate checks anyone on the network can read or change the traffic. | Remove the flag and fix the certificate setup instead. |
| S028 | critical | Crypto-mining tool or mining pool | Mining software uses the user's machine for someone else's profit. | Remove it. |
| S029 | warn | Installs packages from an unusual or unsafe source | An extra package index, a plain-HTTP registry or a trusted-host override can serve a look-alike package instead of the real one. | Install from the official registry over HTTPS with pinned versions and hashes. |

## Hygiene (10 points)

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| C001 | warn | Combined skill descriptions are large for the listing budget | Claude Code lists every skill description in a shared budget (about 1 percent of the context window, an unofficial estimate). Overflow can drop descriptions. | Shorten descriptions or install fewer skills at once. |
| H001 | warn | Stray or generated files shipped in the skill | Caches, OS files and dependency folders bloat the skill and can leak local details. | Delete them and add them to .gitignore. |
| H002 | error | Environment file or key file shipped in the skill | These files usually contain secrets. | Remove it and rotate any credential it held. |
| H003 | warn | Placeholder text left in SKILL.md | Template markers show the skill was never finished. | Fill them in or delete them. |
| H004 | info | No license found | Without a license nobody knows if they may use or share the skill. | Add a LICENSE file or a license field. |
| H005 | warn | File in the skill folder is never mentioned in SKILL.md | The agent only learns about bundled files from SKILL.md, so unreferenced files are dead weight. | Reference the file where it is needed, or delete it. |
| H006 | info | No examples in the body | Examples make agent behaviour far more consistent. | Add one or two short examples. |
| H007 | info | No headings in the body | Headings help both humans and agents navigate. | Structure the body with a few headings. |
| H008 | info | Windows line endings | CRLF can trip up simple frontmatter parsers. | Convert to LF. |
| H009 | info | File starts with a byte order mark | The mark sits before the first line of three dashes, which some parsers do not expect. | Save as UTF-8 without BOM. |
| H010 | warn | Two skills share the same name | Installing both makes one shadow the other. | Give each skill a unique name. |
| H012 | info | Hardcoded home-directory path | A path with a specific user name only works on one machine. | Use a relative path or an environment variable. |

## Contexts

Text-based findings (S003, S004, S005, S006, S007, S008, S009, S010, S011, S012, S014, S017, S021, S022, S023, S024, S025, S026, S027, S028, S029) are tagged with the context of the matched text, shown in brackets in the report and as `context` in JSON. The context decides the severity.

| Context | Meaning | Effect on severity |
| --- | --- | --- |
| executed | Code that runs: a script body, a shell command, a string passed to exec or a shell. | keeps the severity |
| agent-instr | An instruction the agent is told to follow: SKILL.md, agent and command files, shell fences and imperative lines in references, any override or hidden-instruction text (S011, S012) in references, and the command of a hook or MCP entry in a JSON file. | keeps the severity |
| documented | Text in documentation the agent only reads as information. | one level lower |
| hint | A message a script prints or a help string, which describes a command without running it. | one level lower |
| comment | A comment or a docstring. | info |
| defensive | A blocklist, a deny rule, or a sentence that warns against the very thing it names. | info |
| fixture | A file under tests/, test/, fixtures/, fixture/ or __tests__/. | info |

Secrets (S001) are never lowered by context. Hidden characters (S002) are lowered only inside a test folder.

## Plugin rules (only with --plugin)

These rules audit what a plugin installs besides its skills. They run only with `--plugin`, read files only, and are scored in a separate block with its own 0 to 100 score. They do not change a skill's score unless `--plugin-affects-skills` is given.

| Block | Points | Rules |
| --- | ---: | --- |
| Code security | 30 | Security rules (S) run on the scripts, installers, hooks and extension files, and P009 |
| Permissions and hooks | 25 | P002 and P003 |
| Supply chain | 30 | P004, P005, P006, P007 and P012 |
| Consistency and privacy | 15 | P001, P008 and P010 |

| Code | Severity | Check | Why it matters | Fix |
| --- | --- | --- | --- | --- |
| P001 | warn | Plugin manifest is broken or points to files that are missing | Claude Code reads .claude-plugin/plugin.json to load the plugin. Invalid JSON, a missing name or a path to a file that is not there stops parts of it from loading. | Fix the JSON, add the name, and make every path in the manifest point to a real file. |
| P002 | warn | Agent can fetch from the web, run Bash and write files | Web pages can carry hidden instructions. An agent that reads them and can also run commands and write files can be steered into acting on them. | Drop one of the three tools, or narrow what the agent may run, and tell it to treat fetched content as data and never as instructions. |
| P003 | info | Hook runs a command on tool events | A hook runs on your machine every time its event fires, without asking. Broad matchers, values taken from the tool call and interpreters chosen by an environment variable widen what it can do. | Use the narrowest matcher, treat every value from the tool call as data, and call a fixed interpreter. |
| P004 | warn | Script writes downloaded content into the skill folders | Text fetched from the network and saved inside a skill becomes instructions the agent follows. If the source can change (a branch, HEAD) and nothing checks a hash, the skill can change under you. | Pin the download to a commit or tag by default, restrict the host, and compare a known SHA-256 before writing anything. |
| P005 | info | Dependencies are not pinned exactly | A range or a missing lock lets a different version install tomorrow than the one that was reviewed today. | Pin exact versions, keep a lockfile that lists the real packages, and install with hashes where you can. |
| P006 | info | Installer downloads, runs or changes things on the machine | Installers run with your permissions. What they download, whether the source can move, and which config files they edit decide how far you must trust them. | Pin the source to a tag or commit, verify a checksum or signature, and keep edits to your Claude config explicit and reversible. |
| P007 | warn | CI workflow is easy to hijack | Actions that are not pinned to a commit, a wide token, pull_request_target and untrusted text pasted into a run step are the usual ways a workflow is turned against its own repository. | Pin actions to a 40-character commit, declare minimal permissions, and pass untrusted text through env variables. |
| P008 | warn | Versions or counts disagree across the plugin | When the manifest, the packaging files and the installer name different versions or different numbers of skills or agents, users cannot tell what they are installing. | Make every file state the same version and counts, and add a test that keeps them in step. |
| P009 | warn | Code handles credential files without clear care | Credential files should be written readable by the owner only, and reading another tool's sign-in files should be documented. | Create credential files with mode 0o600, and say in the README or PRIVACY file when you read another tool's sign-in. |
| P010 | warn | Code contacts a host the privacy notes never mention | Users read PRIVACY.md and the README to learn who receives their data. A host that appears only in code is a surprise. | List every host the plugin contacts, and why, in PRIVACY.md. |
| P011 | info | Strength: a safeguard the plugin already has | Pinned actions, a threat model, code owners and tests with hostile input make a plugin easier to trust. They add a small bonus to the plugin score and never cancel a critical finding. | Keep them. |
| P012 | info | Unquoted placeholder in a shell command | In a shell, a less-than sign starts a redirect, so a bare placeholder such as <url> breaks the command when someone pastes it as written. | Write the placeholder inside quotes, for example "<url>". |
